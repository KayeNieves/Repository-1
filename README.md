# Repository-1

## Activity 1

This repository documents my activities and practical exercises in Git and GitHub. It demonstrates my understanding of repository management, branch creation, pull requests, and merging changes into the main branch.

Through these activities, I practiced the basic collaboration workflow used in software development to organize code, manage changes, and integrate updates safely.

## Activities Performed

### Repository Creation

**Objective:** To create a GitHub repository for storing and managing project files.

**Description:**
I created a new repository named `Repository-1` on GitHub. This repository serves as the main workspace for my Git and GitHub activities. It provides a centralized location for organizing files, tracking changes, and documenting the progress of my exercises.

**Key concepts learned:**
- Creating and managing a GitHub repository.
- Understanding the purpose of a repository in version control.
- Organizing project files in a centralized workspace.

### Creation of a New Branch

**Objective:** To create a separate branch for making changes without directly affecting the main branch.

**Description:**
I created a new branch in the repository to separate my work from the main branch. A branch allows developers to work on new features, modifications, or experiments independently before integrating their changes into the main project.

This activity helped me understand how branches support organized development and reduce the risk of affecting the main version of a project while making changes.

**Key concepts learned:**
- Creating a new branch in GitHub.
- Understanding the difference between the main branch and a working branch.
- Isolating changes before integrating them into the main project.

### Successful Pull Request

**Objective:** To propose changes from a separate branch for review and integration into the main branch.

**Description:**
After working on the new branch, I successfully created a pull request. A pull request allows changes made in one branch to be presented for review before they are merged into another branch.

This activity demonstrated how developers can review proposed changes, discuss modifications, and ensure that updates are ready to be incorporated into the main project.

**Key concepts learned:**
- Creating a pull request on GitHub.
- Comparing changes between branches.
- Understanding the role of code review in collaborative development.

### Successful Pull Request Merge

**Objective:** To integrate the changes from the pull request into the target branch.

**Description:**
I successfully merged my pull request, integrating the changes from the working branch into the target branch. This completed the process of transferring the proposed updates into the main project.

The successful merge demonstrated how GitHub manages changes between branches and helps maintain an organized development workflow.

**Key concepts learned:**
- Merging changes through a pull request.
- Integrating updates into the target branch.
- Understanding how branches and pull requests work together in version control.

## Summary of Learning

Through these activities, I gained practical experience with the fundamental features of GitHub. I learned how to create a repository, create a separate branch, submit a pull request, and merge proposed changes successfully.

These exercises helped me understand the basic GitHub workflow and how version control supports collaboration, organization, and the safe integration of changes in software development projects.

## Technologies and Tools Used

- **GitHub** – For hosting the repository and managing branches and pull requests.
- **Git** – For understanding version control concepts and managing changes.
